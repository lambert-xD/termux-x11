# Wayland Input Adapter - Implementation Summary

## Files Created

- `app/src/main/cpp/lorie-wayland/input.h` - Public API header
- `app/src/main/cpp/lorie-wayland/input.c` - Implementation

## Architecture

### Threading Model

The adapter uses a **producer-consumer queue** for thread safety:

- **Android main thread** (producer): calls `lorie_wl_input_*()` API functions
- **Wayland display thread** (consumer): calls `lorie_wl_input_dispatch()` to drain the queue and send protocol events

The queue is a ring buffer protected by `pthread_mutex_t` with 256 slots.

### Event Flow (mirrors existing X11 pattern)

```
Android MotionEvent/KeyEvent
  ↓ (Java MainActivity/TouchInputHandler)
LorieView.sendMouseEvent/sendTouchEvent/sendKeyEvent
  ↓ (JNI → new Wayland activity adapter)
lorie_wl_input_pointer_motion() / keyboard_key() / touch_down()
  ↓ (mutex lock)
Event queue push
  ↓ (Wayland thread)
lorie_wl_input_dispatch()
  ↓
wl_pointer_send_motion() / wl_keyboard_send_key() / wl_touch_send_down()
  ↓
Wayland client receives input events
```

### Key Code Reuse

The adapter reuses `android_to_linux_keycode[]` from `lorie.h`. The Wayland keyboard events send Linux input event codes (KEY\_\*) directly, with `WL_KEYBOARD_KEYMAP_FORMAT_NO_KEYMAP` keymap format.

### Seat Capabilities

The `wl_seat` global advertises:

- `WL_SEAT_CAPABILITY_POINTER`
- `WL_SEAT_CAPABILITY_KEYBOARD`
- `WL_SEAT_CAPABILITY_TOUCH`

### Focus Management

- **Keyboard focus**: Set via `lorie_wl_input_set_focus(wl_surface*)`
  - Sends `wl_keyboard.enter` to new focus
  - Sends `wl_keyboard.leave` to old focus
  - Sends `wl_keyboard.modifiers` after enter
- **Pointer focus**: Set via `lorie_wl_input_set_pointer_focus(wl_surface*, x, y)`
  - Sends `wl_pointer.enter` to new focus
  - Sends `wl_pointer.leave` to old focus

### Per-Client Resource Tracking

Each Wayland client that binds a seat gets its own `input_client` struct tracking:

- `wl_pointer` resource
- `wl_keyboard` resource
- `wl_touch` resource

Events are routed to the client that owns the focused surface.

## Known Limitations / TODO

1. **Keymap**: Currently sends `WL_KEYBOARD_KEYMAP_FORMAT_NO_KEYMAP`. Full implementation should generate an xkb keymap file and send `WL_KEYBOARD_KEYMAP_FORMAT_XKB_V1`.
2. **Modifiers**: Always sends zero modifiers. Should track actual modifier state.
3. **Touch focus**: Touch events use keyboard focus surface. Should track per-touch-point surface associations.
4. **Cursor**: `wl_pointer.set_cursor` is a no-op. Should integrate with renderer cursor overlay.
5. **Client destroy tracking**: Does not clean up `input_client` when the wl_client disconnects. Need to add `wl_client` destroy listener.
6. **Serial numbers**: `wl_pointer.frame` events are sent after each individual event. For better protocol compliance, frame events should group related events.

## Build Integration Notes

- `wayland-server-protocol.h` must be generated by `wayland-scanner` during build:
  ```
  wayland-scanner server-header wayland/wayland/protocol/wayland.xml wayland-server-protocol.h
  ```
- The CMake build must add include paths:
  - `wayland/wayland/src` (for wayland-server.h)
  - Build generated directory (for wayland-server-protocol.h)
